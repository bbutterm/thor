# Аудит динамических изображений диалогов — подготовленная работа

Работа добавляет статическую проверку изображений из диалогов к `tools/check_export_assets.py`. Исходный набор для прототипа — `6a5baec`. Здесь описан подготовленный код; на момент написания аудит и тесты ещё не запускались.

Аудит считывает словари `ScreenArt.BACKDROPS` и `WORLD_BACKDROPS`, папки изображений и текущую карту из игрового кода. Он рассматривает `backdrop` сцены, `image` сцены, реплик, вложенных выборов и пулов, а также буквальные вызовы `ScreenArt` и фон `run` для текущей карты с резервом Мидгарда. Значения `none` и пустая строка не требуют изображения. Существующий набор изображений и исключения проверяются отдельно для каждого preset; JSON диалогов также должен присутствовать в `include_filter`. Нераспознанный динамический вызов `ScreenArt`, способ выбора мира или формат карты приводят к ошибке, а не к молчаливому пропуску.

Реестр `tools/deferred_dialogue_assets.json` относится к точной ссылке `(файл, scene id, поле, значение, путь)`, а не ко всему файлу изображения. Отдельно записаны `finale_a/backdrop` с будущим событием победы над Одином и `hel_intro/backdrop` с будущим боссом Хель. В обоих случаях файл есть в исходниках, но исключён из демо. Для отсрочки сверяются условия, триггер, путь после разрешения алиаса и известные источники событий/интро босса. При добавлении активной ссылки на тот же исключённый файл сборка останавливается. При отсутствии файла или изменении условий отсрочка тоже не засчитывается. Вывод `DEFERRED` показывает конкретную ссылку и причину; он не утверждает, что будущая сцена подключена или готова.

Флаг `draft` намеренно не определяет доступность: он есть у всех файлов диалогов и сам по себе не используется загрузчиком для отключения сцен. Изображение `sprites/story/finale.webp` уже включено в демо; наличие его файла не делает финал работающим. Чтобы подключить финал или Хель, необходимо пересмотреть соответствующую запись реестра, включить нужные ресурсы и отдельно проверить игровые события и постановку. Реестр живёт в `tools/`, уже исключённом из экспорта; ни экспортные фильтры, ни игровые файлы в этой работе не меняются.

Ограничения: статическое чтение кода не доказывает полную недостижимость сцен для изменённых сохранений, модов, динамически собранных строк или произвольных обходных вызовов. Проверка поддерживает действующий способ выбора `Run.map`, текущие фиксированные алиасы и известные формы вызовов; при расширении игры эти допущения нужно пересмотреть. Сравнение фильтров использует существующую реализацию `fnmatch`; это не полноценный разбор экспортированного Godot-пакета и не подтверждение успешной загрузки `.ctex` на целевой системе. После активации будущего содержания нужно проверить реальную собранную версию.

## Проверка после разрешения на запуск

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/test_export_assets.py
PYTHONDONTWRITEBYTECODE=1 python3 tools/test_package_playtest.py
PYTHONDONTWRITEBYTECODE=1 python3 tools/check_export_assets.py
git diff --check
```

Тесты включают отсутствующий и исключённый активный файл, алиас фона, вложенный сюжетный кадр, специальные `none` и `run`, изменённую отсрочку, активное второе использование файла, новый источник будущего события или босса, неразрешимый динамический вызов, исключённый JSON и неподдерживаемый preset. Аудит и тесты должны выполняться после окончания ресурсоёмких измерений. Для последующей интеграции кода соблюдать инструкции проекта по импорту после переключения/слияния; новые файлы `tools/` и отчёт сами по себе Godot не вызывают.

# Чтение результатов длительного hitch-прогона

Разборщик работает только с уже сохранёнными файлами `run_hitch_render.sh`: читает их, ничего в них не меняет и выводит JSON в stdout. Для Python нужен только стандартный набор библиотек. Godot и X11 не запускаются.

```bash
python3 tools/read_hitch_log.py /путь/к/папке/прогона
python3 tools/read_hitch_log.py /путь/к/папке/прогона --summary
```

Для сохранения JSON перенаправляйте stdout в **новый** файл вне папки исходного прогона; не перенаправляйте в `godot.log` или другой исходный журнал. Команда возвращает код 0, когда JSON удалось сформировать, даже если сам игровой тест не прошёл. При ошибке чтения она возвращает 2. Файлы прогона остаются в исходном месте; отчёт содержит абсолютные пути, размер и SHA-256 `godot.log`, `metadata.txt` и, если они существуют, журнала кадров `hitches.log`, пользовательского Godot-журнала, Xorg, сервера и `godot-errors.log`.

В полном JSON каждая обнаруженная ошибка содержит номера строк, соседний контекст и следующий непрерывный блок отступов, включая трассу Godot; все распознанные строки всплесков содержат исходный текст, текущие и предыдущие метки. Следует сохранять и сами исходные файлы: они остаются источником всего контекста, включая сообщения, которые разборщик не интерпретирует. `--summary` убирает подробный перечень строк и ошибок, оставляя счётчики и ссылки с хешами.

Основные поля:

- `complete_summary`, `rooms`, `actual_landings`, `launcher_exit`: полнота сводки, залы, реальные приземления и код скрипта. Признаком успешного теста с учётом результата и ошибок служит `launcher_and_test_pass`; отдельно проверяйте сообщения об очистке и счётчик компиляции.
- `event_hitches` и `unmarked_spikes` — итоговые значения самого сценария для скачков **выше полного порога**, второе число в итог теста не входит. В графических прогонах `>>>` означает событие в данном или предыдущем кадре, `~` — событие отсутствует. Строки `spike_rows` и сводка `spike_rows_above_half_threshold` включают также меньшие скачки выше половины порога; `loading` — строки без метки в окне загрузки. Значения в строках округлены сценарием, поэтому для решения о превышении полного порога используйте итоговые числа, а не пересчёт округлённых строк.
- `pso_draw_outside_loading` разбирается только из итоговой таблицы **вне** окон загрузки, а её подробные строки — только из блока непосредственно после таблицы. Сценарий ограничивает список подробностей первыми 40 строками, но печатает суммарный словарь. Если Forward+ сообщает `pso_draw > 0`, `pso_draw_requires_review` становится `true`, даже при успешном тесте. `null` означает недоступные или неразобранные данные. В GL и Dummy счётчиков нет: значение `нет` в их журнале не доказывает отсутствие компиляции шейдеров. Даже нулевое значение имеющегося счётчика относится только к поддерживаемой телеметрии этого прогона и само по себе не доказывает отсутствие всех компиляций.
- `errors` считает `ERROR:` в любой позиции, `Parse Error` и `HITCH FAIL`. Разделение выполняется по положению относительно **единственной** строки итога: `execution_count` до неё, `after_result_count` после неё. Последнее не доказывает конкретную причину ошибки. Если итога нет или он повторяется, фаза остаётся `undetermined`. `warnings_after_result` и `resource_warnings_after_result` выводятся отдельно; `clean_shutdown` равен `null` при отсутствии достоверного итога/кода или достижении лимита журнала.
- `integrity_issues` сообщает о повторяющихся строках сводки и достижении 50 000 000 байт: в последнем случае вывод мог быть обрезан. Наличие этих признаков исключает `launcher_and_test_pass`.

Общее прохождение Н11 нельзя выводить из кода запуска, счётчика фризов, `clean_shutdown` или `pso_draw` по отдельности: необходимо совместно рассмотреть оба рендерера, события и немаркированные скачки, источники ошибок и ограничения программного рендера.

Проверка разборщика:

```bash
python3 -m unittest -v tools.test_read_hitch_log
```

Набор включает синтетические записи со смешанными ошибками и контекстом, различными фазами, повреждёнными и дублированными итогами, отсутствующими и ненулевыми `pso_draw`, ложной таблицей внутри окна загрузки, лимитом вывода и проверкой неизменности исходника. При наличии исторического прогона `gl-final-6a5baec` дополнительно проверяются 10/10 залов, 42 приземления, 29/34 скачка, 54 ошибки до итога, две после него, предупреждение ObjectDB и код 1. Исторический GL использует llvmpipe; данные нельзя переносить на производительность реального GPU.

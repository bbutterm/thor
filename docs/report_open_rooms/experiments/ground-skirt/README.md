# Проверка разбиения рамки земли Н3

У `Dress/GroundSkirt` одна поверхность из шести полос земли вокруг зала. Её общий AABB занимает квадрат ±30 м; для GL он может пересекать факелы даже там, где соответствующие треугольники удалены от источника. Гипотеза: разбить поверхность на меньшие части, чтобы движок точнее отсекал геометрию и связанные источники света.

Стенд `tests/room_skirt_compare.tscn` **не изменяет игровую сцену**: временно заменяет рамку шестью исходными полосами либо двенадцатью отдельными исходными треугольниками. Порядок, координаты, нормали, касательные (если есть), цвета, UV, материал, трансформация, слои и тени сохранены. При неожиданной структуре исходной поверхности стенд останавливается с ошибкой.

В одном процессе сравниваются исходный зал `db952fa`, Н3 с общей рамкой и два варианта разбивки. Камера, окружение и 44 неподвижных врага одинаковы; игрок и враги заморожены. После 15 кадров прогрева — два попеременных прохода по 45 кадров на вариант. Время измеряется системными часами. Это **сравнение рендера**, не реальный бой и не замер на целевой видеокарте.

## Результаты

Godot 4.6.3, GL Compatibility, программный Mesa llvmpipe, 320×180. Отдельный Xorg и изолированное пользовательское хранилище; тяжёлых параллельных процессов не запускали. CPU контейнера ограничен четырьмя ядрами по квоте; заметен шум по времени. В пределах каждого запуска модели и окружение одинаковы; во втором процессе случайные варианты внешнего вида врагов отличаются, поэтому сравнивать значения следует внутри одного процесса.

| Ограничение потоков Mesa | Вариант | Среднее, мс: проходы 1 / 2 | Медиана, мс: проходы 1 / 2 | p95, мс: проходы 1 / 2 | Draw calls |
|---|---|---:|---:|---:|---:|
| по умолчанию | старый зал | 119,72 / 124,89 | 117,79 / 122,39 | 132,84 / 144,29 | 2507 |
| по умолчанию | Н3, рамка целиком | 138,56 / 137,13 | 137,09 / 133,71 | 151,94 / 166,33 | 1832 |
| по умолчанию | Н3, шесть полос | 134,70 / 140,33 | 132,57 / 137,29 | 154,82 / 167,90 | 1836 |
| по умолчанию | Н3, 12 треугольников | 139,21 / 135,00 | 137,59 / 135,06 | 154,05 / 148,52 | 1841 |
| `LP_NUM_THREADS=4` | старый зал | 133,09 / 118,77 | 127,78 / 117,80 | 158,10 / 130,57 | 2489 |
| `LP_NUM_THREADS=4` | Н3, рамка целиком | 159,23 / 142,06 | 158,31 / 138,05 | 178,80 / 167,41 | 1814 |
| `LP_NUM_THREADS=4` | Н3, шесть полос | 145,84 / 143,57 | 142,88 / 140,38 | 171,94 / 170,26 | 1818 |
| `LP_NUM_THREADS=4` | Н3, 12 треугольников | 141,42 / 151,73 | 137,73 / 153,40 | 165,13 / 166,33 | 1823 |

В обоих запусках оба варианта разбивки совпали с исходным Н3 во всех четырёх поворотах камеры: по **57 600 из 57 600 пикселей** в каждом сравнении. Пример: [исходная рамка](original.png), [шесть полос](six-strips.png).

Устойчивое ускорение не подтверждено: результаты вариантов меняются местами между проходами, а старый зал остаётся быстрее. **Разбивка не включена в игру.** Эти замеры не доказывают ни наличие, ни отсутствие регрессии на реальном GPU.

## Повторение

```sh
bash tests/run_skirt_compare.sh
LP_NUM_THREADS=4 bash tests/run_skirt_compare.sh
```

Скрипт требует Godot 4.6.3, Xorg с dummy-драйвером, Mesa llvmpipe и `xdpyinfo`; делает `--import`, создаёт свой дисплей и пользовательский каталог, ограничивает логи до 50 МБ и сохраняет результаты в `/workspace/thor-artifacts/room-skirt`. Пути можно заменить переменными `THOR_SKIRT_PROJECT` и `THOR_SKIRT_ARTIFACTS`. На другом окружении выполняйте сравнение без параллельных нагрузочных процессов.

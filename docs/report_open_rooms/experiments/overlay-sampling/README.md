# Н3: пропуск чтения белой текстуры второго слоя

**Результат: Н3 остаётся медленнее старого зала; устойчивый выигрыш относительно исходного Н3 не подтверждён. Игровые изменения не применены.** Замер сделан на программном GL, а не на целевой видеокарте и не во время настоящего боя.

## Гипотеза и охват

`shaders/world_surface.gdshader` всегда выполняет анизотропное чтение `overlay_tex`, даже когда используется белая заглушка `hint_default_white`. Для такой текстуры умножение цвета на белый не меняет результат. Эксперимент добавляет один условный параметр: по умолчанию чтение включено, а для материалов без текстуры отключено. Один и тот же шейдер и пайплайн используются для обоих случаев. Материалы с настоящей текстурой продолжают её читать.

В [патче](candidate.patch.gz) параметр задан для **64** общих и встроенных в сцены материалов с белой заглушкой; **12** материалов с текстурой оставлены включёнными. Генератор выводит параметр из наличия `overlay_tex`. Если вручную добавить текстуру к материалу с отключённым чтением, параметр необходимо снова включить. В первой комнате стенд обнаружил восемь уникальных материалов с белой заглушкой и один с текстурой. Кандидат не проверялся во всех игровых ситуациях и не предназначен для переноса без повторных тестов прогрева и платформ.

## Метод

Godot 4.6.3, GL Compatibility, Mesa llvmpipe, `LP_NUM_THREADS=4`, отдельный Xorg, 320×180. В одной игровой сцене используются одна и та же камера и **44 анимированных врага** (11 воинов, 33 корма); физика и ИИ врагов выключены. Старый зал — `tests/fixtures/room_01_before_b0.tscn` из `db952fa` с окружением текущей карты, новый — Н3. Внутри одного процесса варианты переключаются без пересоздания врагов. Каждый прогревается, затем идут три цикла `старый → Н3 без оптимизации A → Н3 с оптимизацией → Н3 без оптимизации B`, по 45 кадров на вариант. A/B позволяют увидеть дрейф; это не FPS полноценного боя.

## Изображение и состояние запуска

Две фазы анимации и четыре поворота камеры дали восемь пар кадров 320×180. Девятая пара — отдельная галерея всех девяти типов материалов на разных гранях при 960×540. **Во всех девяти парах нет различающихся пикселей**; каждая картинка содержит более 256 цветов. [Пример кадра](scene.png), [галерея](gallery.png), [результат сравнения](pixels.txt). Фазы анимации друг от друга отличаются. Это ограниченная проверка ракурсов и GL, не доказательство совпадения для всех сцен, платформ и движения.

Стенд вывел `OVERLAY SAMPLING BENCH COMPLETE`, сам процесс Godot завершился с кодом 0, но при завершении записал **два `ERROR: Texture with GL ID ... leaked 349524 bytes`** и предупреждение об оставшихся объектах. Причина не установлена; похожие сообщения наблюдались и в отдельном эксперименте Skin, но это не доказывает общую причину. Поэтому строгий скрипт запуска завершился **с ошибкой 1**, хотя изображения были сохранены и отдельно сравнены. Это не чистый проход. Полный [вывод Godot](godot.log.gz) и [метаданные](metadata.txt) сохранены.

## Повторение

Работать в отдельном чистом checkout `codex/preview-work` с базой `56c8b2f`, не параллельно с тяжёлыми процессами; нужен Xorg с dummy-драйвером и Pillow для Python. Следующие команды применяют **экспериментальный** патч к этому checkout и копируют [исходники стенда](bench/) в `tests/`:

```sh
gzip -dc docs/report_open_rooms/experiments/overlay-sampling/candidate.patch.gz | git apply
for src in docs/report_open_rooms/experiments/overlay-sampling/bench/*.txt; do
  name=$(basename "$src" .txt)
  cp "$src" "tests/$name"
done
THOR_OVERLAY_PROJECT="$PWD" THOR_OVERLAY_ARTIFACTS=/tmp/thor-overlay-sampling \
  LP_NUM_THREADS=4 bash tests/run_overlay_sampling_bench.sh
```

Скрипт изолирует настройки и данные Godot, ограничивает журнал 50 МБ и проверяет ресурсы и сравнение кадров. На совершенно новом checkout первый импорт может сначала пожаловаться на ещё не импортированный шрифт; строгая проверка остановит скрипт, и после завершения импорта его следует запустить повторно. Для текущего результата предупреждения о двух GL-текстурах описаны выше и не подавлены.

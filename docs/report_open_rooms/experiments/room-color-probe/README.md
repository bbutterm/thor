# Диагностический стенд стоимости цвета

Этот стенд **подготовлен, но ещё не запускался**. Он не меняет игровые материалы и не входит в экспорт: `tests/*` исключены из `export_presets.cfg`. Эксперимент предназначен для оценки потенциальной стоимости вычисления цвета, а не сохранения качества и не является доказательством ускорения.

В одном процессе сравниваются исходный зал до Б0 (`tests/fixtures/room_01_before_b0.tscn`), исходный Н3, упрощение только `Dress/FloorVisual`, только `Dress/GroundSkirt`, только `Dress/Backdrop/Ground`, двух поверхностей окружения вместе и всех трёх вместе. Камера, геометрия, окружение и 44 неподвижных врага общие; ИИ и боевые действия выключены. Сцена ставится на паузу, каждый вариант отдельно прогревается, затем выполняются два прохода по 60 кадров в прямом и обратном порядке. Измеряется системное время кадра, выводятся среднее, медиана, p95 и draw calls. PNG каждого варианта сохраняется только для проверки того, что нужные поверхности действительно изменились.

`surface_color_probe.gdshader` намеренно заменяет цветовую композицию однотонным цветом, а шероховатость — средним двух исходных значений. Текстуры цвета, оба слоя и шум визуально теряются. Параметры карты нормалей, затенение по цвету вершин, расчёт AO, модель освещения и геометрия остаются; свет может выглядеть иначе из-за изменённого цвета и шероховатости. Это другая шейдерная программа, поэтому разницу нельзя считать строгой верхней границей будущего ускорения: драйвер может оптимизировать её иначе, а полученный вариант визуально непригоден для игры.

Запускать только в выделенное окно без других тяжёлых процессов и после импорта проекта. Нужен X11/виртуальный дисплей; `--headless` не измеряет рендер. Пример для llvmpipe:

```sh
set -o pipefail
XDG_DATA_HOME=/tmp/thor-color-probe LIBGL_ALWAYS_SOFTWARE=1 \
  godot --path . --fixed-fps 60 --rendering-method gl_compatibility \
  --audio-driver Dummy --resolution 320x180 \
  res://tests/room_color_probe.tscn -- /tmp/thor-color-probe-shots \
  2>&1 | head -c 50000000 > /tmp/thor-color-probe.log
```

При необходимости второй аргумент после каталога кадров задаёт количество измеряемых кадров в проходе; минимум 10, по умолчанию 60. До публикации результатов нужно проверить полноту журнала, отсутствие ошибок компиляции шейдера, правильность количества врагов и кадров, а также сравнить с исходной сценой. Для выводов о пользовательской производительности необходимы целевая видеокарта, другой рендерер, больше ракурсов и активный бой.

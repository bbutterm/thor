# Прототип вспышки врагов для GL Compatibility — 28.10.2026

Статус: изменение перенесено в сводную рабочую ветку; оно не подтверждено на аппаратной видеокарте и не проверено длительным забегом после объединения. Воспроизведённое переполнение при 44 живых врагах не повторилось в двух однозальных прогонах с прототипом. При выходе из игровых тестов остаются ошибки утечки двух GL-текстур; одинаковые ошибки есть и в исходных контрольных прогонах. Нельзя считать весь прогон чистым только по коду выхода 0.

## Изменение

GL Compatibility создаёт один `ShaderMaterial` на врага при появлении и переиспользует его на всех частях модели, включая бочку Свена. Три параметра исходной вспышки стали обычными `uniform`; формула, `render_mode`, `source_color` и `render_priority` совпадают с исходными. Цвет и сила остаются независимыми для каждого врага. Обводка синхронизирует `next_pass` активных материалов при настройке и прогреве. На Forward+ сохраняются исходный материал и `instance uniform`; после переноса добавлена проверка метода рендера, поэтому синхронизация GL-материалов там не обходит группу обводки. Реальный Forward+ в этой серии не запускался.

## Условия и границы проверки

- Godot 4.6.3.stable.official.7d41c59c4; Linux; GL Compatibility, OpenGL 4.5 Core, Mesa 25.0.7-2+deb13u1, llvmpipe LLVM 19.1.7, 256 bits. Это программный рендерер, не измерение аппаратного GPU.
- Отдельные процессы, `LP_NUM_THREADS=4`, `LIBGL_ALWAYS_SOFTWARE=1`, `--fixed-fps 60 --audio-driver Dummy --rendering-method gl_compatibility --resolution 320x180`, новый `XDG_DATA_HOME` для каждого процесса. Журналы ограничены 50 МБ на файл. Поиск `ERROR:` выполнен по вхождению в любом месте строки.
- Исходные четыре однозальных лога относятся к отдельному прототипу перехода между залами; его `scenes/game.gd` SHA-256 `ee7fc058e14d1963587175537938d468d77477a3fd987ee6ada14ca7e0bafb54`. Новые логи используют `game.gd` SHA-256 `9fd03ccc663cfd727f46659e83fccb5871798008bd82fdcd0da3653da3ae6572`. В самом сценарии переходов не было. Поэтому предыдущее A/A и новое C/C — проверка воспроизведения, а не строгое сравнение времени.
- Отдельный A/B/A/B для времени выполнялся на одной ревизии `b94dc10` с одинаковым `game.gd`; отличались исходные файлы вспышки и прототип. Внешность до добавления врагов фиксирована, манифест 20 врагов и 108 мешей во всех четырёх запусках совпал: SHA-256 `85a0314fa9ddceb0140526fd30de192d84c541f3589acf5e9e1843e051c4a16b`.
- Сценарий производительности отличается от исходного: фиксирует внешность, сохраняет полный `Perf.record_all`, отключает запись фризов в файл на измеряемом участке и выдерживает два кадра после сбора манифеста. Одинаковый файл применён к A и B. Вызовы `take_hit` и создание группы замерены синхронно по настенным часам; они включают возможное ожидание потока и не являются временем GPU. Продолжительность кадра включает процесс, ожидание и рендер.

## Вид и поведение

- `tests/outline_test.tscn` под реальным GL: 64 проверки, 0 неудачных утверждений. Проверены независимость двух врагов, переиспользование и освобождение материала после смерти, элита через `Loot`, реальные состояния огня/тока/заморозки через `ElementStatus`, 44 одновременные вспышки, обводка вкл/выкл и прогрев. При выходе — две ошибки утечки GL-текстур; они не скрыты в журнале.
- `tests/enemy_flash_equivalence.tscn`: два одинаковых меша в независимых viewport в одном GL-процессе, исходный и новый материал; урон, замах, элита, лёд и смешанные состояния с обводкой и без. Все 12 пар изображений 128×128 совпали точно: максимальная разница канала 0/255. Это проверка шейдера на тестовом меше, а не визуальная оценка всего игрового кадра; изображения сохранены в `pixels/`.
- В headless первая версия теста обводки дала 61 OK / 1 FAIL: счётчик эффектов сравнивался через разные кадры, пока частицы затухали. После переноса сравнения в один кадр повтор дал 62 OK / 0 FAIL. При выходе повторного headless были `ERROR: 19 resources still in use at exit`; отдельный headless запуск стенда производительности — 15 ресурсов. Эти сообщения и первый неудачный журнал сохранены.

Все журналы и исходные массивы лежат в `logs/` и `frames/`; `.log.gz` содержат полный stdout/stderr без отброшенных сообщений. Сырые оригиналы и изолированные данные этих запусков также оставлены в `/workspace/thor-artifacts/gl-enemy-flash-prototype/` и `/workspace/thor-artifacts/room-transition-gl/`. `docs/` и `tests/` исключены из игрового экспорта.
